## 넘길 값

- 장수 = **썸네일 1 + 본문 장 + CTA 1**. 본문 장수는 3-3 이 정한다 — **글자 없는 사진은 글 캡처에 합쳐 1장**, 글자 박힌 사진(표·메뉴판)만 따로 1장씩 (2026-09-16 사람 지시로 바뀜 → [3-3 문서](X인용_3-3단계_본문.md))

- `layout_overrides` 는 **모든 순번을 빠짐없이** — 예) 사진 2장짜리(총 5장)면 `{"0":"썸네일","1":"본문(X인용)","2":"본문(X인용)","3":"본문(X인용)","4":"CTA(X인용)"}`.
  빠진 순번은 표지로 떨어진다.
- ⚠ **표지에 `items` 를 넘기면 로고가 덮인다 (2026-09-16 2차).** 렌더러는 `items` 가 있을 때만 `kind: image` 장식을 칸으로 쓴다(`carousel_renderer.py` 5b `if not grid and items`).
  지금 `썸네일` 의 이미지 장식은 로고 하나뿐이라, `items` 를 비워 두면 로고가 템플릿 그대로 그려진다. 넘기려면 칸 0 에 로고 주소를 다시 넣어야 한다 — `https://3-35-18-166.sslip.io:3443/api/images/template-assets/2/e394e3e3de925288.png`
  (아래는 X 글 캡처 칸이 있던 2026-09-16 1차 때의 기록이다: 칸 0 = 로고, 칸 1 = X 글 캡처.)
- `slides` 에 확정 문구를 **반드시** 넘긴다. 안 넘기면 서버가 문구를 새로 짓는다.
- 3-3 문구는 **글자 그대로** 옮긴다(다듬지 않는다).
- ⚠ **CTA 장의 검정 막(`rgba(0,0,0,0.35)`)은 저장 전에 지운다** (2026-09-16 사람 지시 · 모든 축 공통 → 방 지침서 「CTA 낱장의 검정 막은 뺀다」). 본문 막은 그대로 둔다.
- ⚠ **썸네일 장의 검정 막도 지운다 (2026-09-17 사람 지시 — 「x인용 캐러셀 썸네일에 검정색 투명도 들어간 배경 빼줘. 하단 그라데이션 말고」).**
  낱장 전체를 덮는 `rect`(채움이 `rgba(0,0,0,…)` 단색)만 지우고, **템플릿의 하단 검정 그라데이션(x0 y490 · 1080×860, `linear`)은 남긴다** — 그게 훅 글자를 읽히게 한다.
  만든 뒤 `canvas_slides[0].objects` 를 열어 단색 검정 rect 가 없는지 눈으로 본다.
- ⚠ **썸네일 하단 그라데이션은 저장 전에 편집기 형식으로 바꾼다 (2026-09-17 솔희님 제보 — 「캐러셀 생성하면 투명으로 보여」).**
  렌더 결과의 그라데이션 채움이 템플릿 형식 `{type, angle, stops}` 그대로라 편집기가 그라데이션으로 못 그린다.
  `{type:"linear", coords, colorStops}` 로 바꿔 저장한다 — 원클릭은 `studio_steps.py` `_tidy_canvas_slides` 가 막 제거와 함께 한다(봇도 같은 계산을 쓴다).
- **표지 사진 1장은 표지와 CTA 에만 넣는다** (2026-09-16 사람 지시 — 「본문에는 배경으로 넣는 거 제외, 썸네일·CTA만 배경 동일하게」). `user_image_urls` 에 **0번과 마지막 순번만** 같은 주소로 적는다.
  안 넣으면 `CTA(X인용)` 는 배경 종류가 「키워드 사진」이라 서버가 엉뚱한 사진을 한 장 깔 수 있다.
- ⚠ **본문 글자는 흰색 그대로 둔다 (2026-09-16 2차 — 템플릿이 바뀌었다).** 본문 배경이 **검정**이고 템플릿값이 `#ffffff` 80px 이라 그대로 읽힌다. 자동 대비는 돌지 않는다(렌더 결과 실측 `#ffffff`). 검정으로 바꾸지 마라.
  ⚠ **본문 이미지 칸이 739×825 라 1:1 이미지는 좌우가 5%쯤 잘린다**(cover-fit). 3-3 캡처는 흰 여백을 두르고 있어 지금은 여백만 잘린다 — 가장자리에 글자가 닿는 카드는 위아래 여백을 더 붙여 넘긴다.
  아래는 흰 배경·검정 글자이던 2026-09-16 1차 때의 기록이다.
  아래는 본문에 사진을 깔던 때의 기록이다 — ⚠ **본문 글자색은 사진 밝기를 보고 정한다 (2026-09-16).** 배경에 사진이 깔리면 렌더러의 자동 대비가 아예 돌지 않아(`carousel_renderer.py` `text_on_solid = not has_photo_bg`)
  템플릿값 `#000000` 검정이 그대로 나온다. **어두운 사진이면 저장 전에 `#FFFFFF` 로 바꾼다.** 밝은 사진이면 검정 그대로 둔다.
  (2026-09-15 에는 본문에 검정 그라데이션이 깔려 있어 무조건 흰색으로 되돌렸다 — 그 규칙은 끝났다.)
  아래는 2026-09-15 상황의 기록이다(그때는 본문에 검정 그라데이션이 깔려 있었다) — **본문 글자가 검정으로 바뀐다 (2026-09-15 1회차 확인).** `본문(X인용)` 은 배경이 흰색이라 렌더러의 자동 대비(`carousel_renderer.py` 「Auto-contrast」)가
  흰 글씨를 `#1A1A1A` 로 뒤집는데, 글자는 **검정 그라데이션 위**에 있어 편집기에서 거의 안 보인다.
  → 렌더 결과를 저장하기 전에(또는 만든 뒤 PATCH 로) 본문 장 `textbox` 의 `fill` 을 **`#FFFFFF`** 로 되돌린다. 코드는 아직 고치지 않았다.

## 만든 뒤 확인

- 편집기 화면을 찍어 **모든 장의 글자와 캡처가 보이는지** 본다 — 캡처가 칸 밖으로 잘리거나 글자가 넘치지 않는지.
- ⚠ **썸네일 훅은 줄마다 12자(2026-09-15 15→12)지만 칸 폭은 911px · 글자 100px 이다.** 12자 줄이 칸을 넘치는지 첫 회차에서 편집기로 확인하고 결과를 여기 적는다.
- 넘친 칸이 있으면 3-3 문구를 줄여 다시 짓는다(봇이 손으로 자르지 않는다).
