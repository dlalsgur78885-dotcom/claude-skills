## 디스코드 답변 쓰는 법 (2026-10-21 트립앤라이프 지시)

**쉬운 버전을 먼저, 자세한 것은 그 아래.** 긴 답은 두 칸으로 나눈다.

```
한 줄 결론
[간단히] 짧은 문장 2~4개. 한 줄에 한 가지만.
[자세히] 근거·숫자·예외는 여기에 몰아 쓴다.
```

- **빈 줄을 만들지 않는다.** 줄바꿈은 **문단이 바뀔 때만**. 목록 항목 사이는 붙여 쓴다.
  (2026-10-21 추가 — 빈 줄 때문에 글이 길어 보인다는 지적)
- **한 줄에 한 가지만.** 쉼표로 세 가지를 잇지 말고 줄을 바꾼다.
- **쉬운 말로.** 전문 용어·영어 약자는 괄호로 한 번 풀어 준다.
- 표는 칸이 정말 맞아떨어질 때만. 보통은 `·` 목록이 낫다.
- 짧은 답(두세 줄)은 그냥 문장으로. 억지로 두 칸으로 나누지 않는다.

## 낱장(부품) 이름 규칙 (2026-10-21 확정)

**템플릿을 여러 개로 쪼개지 않는다.** 한 템플릿 안에 낱장을 여러 벌 두고 골라 쓴다.
로고·색·폰트 같은 공통 요소를 한 곳에서만 고치기 위해서다.

이름은 `<자리>_<유형>` 으로 적는다. 자리는 `표지` · `본문` · `CTA` 셋뿐이다.

| 자리 | 예 |
|---|---|
| 표지 | `표지_사진` · `표지_캡처` |
| 본문 | `본문_사진` · `본문_사진자막` · `본문_캡처` · `본문_텍스트` |
| CTA | `CTA` (한 벌이면 접미사 없이) |

> ⚠ **낱장 이름이 한 글자만 달라도 렌더러가 조용히 표지로 떨어진다**(캐러셀 553).
> 축 설정(`studio_steps.py` 의 `cover_layout` · `body_layout` · `cta_layout`)에 적힌
> 이름과 **글자 단위로 같아야** 한다. 이름을 바꾸면 축 설정도 같이 바꾼다.

## 템플릿 96 은 브리지 세션이 맡는다 (2026-10-21 트립앤라이프 확정)

`트립앤라이프(종합)`(id 96, junhyeok 계정)의 **생김새는 브리지 세션(클로드)만 고친다.**
캐러셀봇은 **쓰기만 한다** — 96 으로 캐러셀을 만드는 것은 자유, 내용은 건드리지 않는다.

| 하는 일 | 누가 |
|---|---|
| 96 의 낱장 추가·삭제·이름 변경 | 브리지 세션 |
| 로고·좌표·글자 크기·색·그림자·배경 그라데이션 | 브리지 세션 |
| 축 설정(`studio_steps.py` 의 `cover_layout`·`body_layout`·`cta_layout`)을 낱장 이름과 맞추기 | 브리지 세션 |
| 96 으로 캐러셀 만들기, 수집·소재 고르기, 사진·이미지, 캡션 | 캐러셀봇 |

- 캐러셀봇의 템플릿 도구는 `list_templates` · `share_template` 둘뿐이라 **원래 고칠 수가 없다**
  (2026-10-21 `캐러셀 봇/src/tools.js` 확인). 사람에게 "편집기에서 이렇게 바꿔 달라" 고
  유도하는 것도 하지 않는다 — 템플릿 요청은 그대로 브리지 세션으로 넘긴다.
- **둘이 같은 템플릿을 동시에 고치면 나중 저장이 앞 것을 통째로 덮는다.** 그래서 한 쪽만 쥔다.
- 낱장 이름과 축 설정은 **글자 단위로 같아야** 한다(위 §낱장 이름 규칙). 템플릿만 바꾸고
  코드를 안 바꾸면 렌더러가 조용히 첫 낱장(`표지`)으로 떨어진다 — 그래서 둘을 한 쪽이 쥔다.
- 96 은 junhyeok 계정 것이라 solhee 방에서는 보이지도 않는다.

## 캡처카드 만드는 법 (2026-10-21 캐러셀 903 으로 실제로 돌려 봄)

X·유튜브 글을 **한국어로 갈아 끼운 화면 캡처**로 만든다. 직접 그리지 않는다 —
X인용 축이 쓰던 파이프라인을 그대로 쓴다(`backend/app/services/x_search.py`).

| 단계 | 하는 것 |
|---|---|
| 1 | 소재를 Togetter 에서 찾는다 — `python tmp/togetter_hot.py` → `tmp/togetter.json`(pv·날짜순) |
| 2 | 정리글이 아니라 **원문 X 글**로 내려간다. 수치는 `api.fxtwitter.com/status/<id>` 에서 그대로 받는다 |
| 3 | 반응은 `api.fxtwitter.com/2/conversation/<id>` — 좋아요순으로 고른다(**grok 안 쓴다 · 토큰 0**) |
| 4 | 한국어 번역을 직접 쓰고 `x_search.capture_card(id, korean)` · `capture_reply({...})` 로 찍는다(739×825) |
| 5 | `studio_remote.upload_image()` 로 올리고, 낱장 `캡처카드` 에 `items[0].image_url` 로 넣는다 |

- **렌더에 세 가지를 함께 넘긴다** — `slides[i].items[0].image_url` · `user_item_image_urls` ·
  `layout_overrides`. 하나라도 빠지면 캡처가 조용히 사라진다.
- ⚠ **답글 카드에 조회·답글·재게시 수를 안 주면 화면에 `0 답글 0 재게시` 가 그대로 찍힌다.**
  FxTwitter 에서 받은 값을 그대로 넣는다(903 에서 한 번 틀려 다시 찍었다).
- 글쓴이 한 줄(아바타·이름·아이디)은 헬퍼가 브라우저에서 **블러**한다 — 따로 가릴 것 없다.
- 자막(`headline`)은 **한 줄**이다. 수치를 반올림해 적지 않는다(「1,300만 조회」 금지).
- 본보기 스크립트는 `.work/cap96/run.py` — 표지 + 캡처카드 2 + CTA 4 장을 만든다.
- ⚠ **낱장 이미지 칸에 둥근 모서리(`corner_radius`)를 주면 편집기가 그 칸에 clipPath 를 걸어
  이미지가 칸 밖으로 못 나간다**(2026-10-21 트립앤라이프 「이미지를 옮길 수가 없다」).
  `캡처카드` 는 0 으로 바꿨다 — X 캡처는 이미 제 모서리가 둥글어 잃는 것이 없다.
  이미 만든 캐러셀은 편집기가 저장할 때 clipPath 를 통째로 구워 넣으므로, 템플릿만 고치면
  안 되고 **그 캐러셀의 `clipPath` 와 `data._cornerRadius` 도 지워야** 풀린다.

## 글만 있는 장은 **직접 쓰지 않는다 — 캡처로 만든다** (2026-10-21 트립앤라이프 지시)

레퍼런스의 「긴 글 한 판」은 전부 **진짜 화면 캡처**였다 — #35 는 Grok 번역 화면,
#33 은 X 글, #41 도 글 캡처다. 검정 배경에 우리가 타이핑한 글은 티가 난다.

- 긴 글이 필요하면 **X 답글을 각각 임베드 그대로 찍어 검정 배경에 쌓는다**(compact 로 자르면 **5장**이 들어간다)
  (`backend/scripts/x-reply-card.mjs` → 폭 940 으로 맞춰 세로로 붙임). 좋아요·조회·시각이
  실제 화면값이라 캡처로 읽힌다. 본보기 `.work/cap96/stack.py` · 캐러셀 904 네 번째 장.
  **카드는 `"compact": true` 로 찍는다** — 게시 시각·조회수 줄에서 끊어 좋아요·답글 버튼 줄을
  뺀다(2026-10-21 트립앤라이프 「면적이 너무 넓다」). 안 주면 예전처럼 버튼 줄까지 나온다.
- 원문이 길면 그 글 자체를 `x-capture.js` 로 찍어 한 판으로 쓴다.
- **Grok·ChatGPT 화면은 흉내 내 그리지 않는다.** 남의 서비스 화면을 지어내는 것이다.
  번역을 보여야 하면 원문 캡처에 한국어를 갈아 끼운 우리 캡처를 쓴다(이미 그렇게 한다).
- `텍스트` 낱장은 남겨 두되 **기본으로 쓰지 않는다.**
