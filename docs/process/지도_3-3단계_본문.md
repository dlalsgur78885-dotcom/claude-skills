# 지도 — 3-3단계 본문 내용

작성: solhee 방 / 2026-08-26 회차 (주제: 교토 니시키시장)
최종 수정: 2026-08-28 4회차 (**가이드 주소와 구글맵 주소가 다를 때는 구글맵을 쓰고 말한다** / 매장 3곳을 한 번에 · 특징 3~4줄 · 매장당 사진 5장 = 구글맵 3 + 네이버 2 · 매장당 링크 하나 / 콜라주 컷 제외 / 2026-08-27 네이버 우선 · 워터마크 없는 것 · 세로형)

## 이 단계에서 하는 일

본문 **3개**를 만든다. 1개 = 1페이지, 낱장은 `본문_지도`.

**본문 글과 그 장의 배경 사진은 한 묶음이다.** 글을 먼저 확정받고 사진을 따로 묻지 않는다.
**매장 3곳을 한 번에** 낸다 — 장소마다 「본문 + 사진 5장」을 붙여서 보내고, 사람이 한 번에 「본문 확정 + 사진 몇 번」을 고른다.

## 전달 형식 — 매장 3곳을 한 번에 (2026-08-28 사람 지시)

사람이 준 형식 그대로 낸다. 임의로 순서를 바꾸거나 칸을 빼지 않는다.

```
1. 매장명 [HEADLINE]
📍위치 [SUBHEADLINE]
특징 설명 문구 3~4줄 (요다체 / 관광객 타겟 / 자연스럽게)  [BODY]

사진 5장 → <링크 하나>

2. 매장명 [HEADLINE]
📍위치 [SUBHEADLINE]
특징 설명 문구 3~4줄  [BODY]

사진 5장 → <링크 하나>

3. 매장명 [HEADLINE]
📍위치 [SUBHEADLINE]
특징 설명 문구 3~4줄  [BODY]

사진 5장 → <링크 하나>
```

- **세 곳을 한 메시지에 전부** 담는다. 한 곳씩 나눠 보내지 않는다.
- 매장 사이는 빈 줄로 띄운다.
- **정확한 정보 확인 필수** — 매장명·위치·특징은 지어내지 않는다 (→ 아래 [정확한 정보 확인 필수](#정확한-정보-확인-필수)).

> **메시지가 길어 잘릴 때** (2026-08-27 추가) — 한 번에 다 못 보내면 **본문 3개를 먼저 보내고,
> 바로 다음 메시지에 사진 링크를 이어 보낸다.** 본문만 보내고 턴을 끝내지 않는다.

## 본문·사진 링크는 **낸 자리에서 이 문서에 적는다** (2026-08-28 추가)

**사람에게 본문 3개를 보낸 그 턴에 이 문서의 「이번 회차 본문」을 채운다.** 사람이 고르기를 기다리지 않는다.
(고른 번호는 나중에 한 줄 더 적으면 된다.)

- 이유 — 대화가 길어지면 **앞쪽 메시지가 잘려 나간다.** 사진 후보를 만드는 턴에 캡처·이미지가 많이 오가서 특히 잘 밀린다.
- 실제 사고(2026-08-28 전국 체험 회차) — 본문 3개를 보낸 뒤 사진 선택을 받는 사이에 **본문 원문이 컨텍스트에서 사라져**
  사람에게 다시 붙여 달라고 부탁해야 했다. 갤러리는 링크가 남아 복구됐지만 **글은 어디에도 없었다.**
- 그러니 **본문 세 칸 + 갤러리 링크(매장별)** 를 낸 즉시 적는다. 링크만 있으면 사진 후보는 다시 열어 볼 수 있다.
- **한 장소에 갤러리를 두 번 만들었으면 둘 다 적고 무엇이 다른지 한 줄 붙인다.**
  같은 장소에 갤러리가 둘이면 「4번」이 어느 쪽 4번인지 알 수 없게 된다(같은 회차에서 실제로 겪었다).

### 고른 사진의 **전체 주소도 그 자리에서 적는다** (2026-08-31 추가)

사람이 번호를 말하면 **그 번호가 가리키는 URL 을 갤러리에서 확인해 이 문서에 적는다.**
번호만 적어 두면 4단계에서 다시 갤러리를 열어 맞춰 봐야 한다.

- 갤러리 페이지는 토큰 없이 열리므로 `WebFetch` 로 열어 카드 순서대로 `img` 주소를 읽으면 된다
  (`backend/app/api/galleries.py` — 번호는 `images` 배열 순서 그대로다).

## 한 장에 들어가는 것

| 칸 | 슬롯 역할 | `slides` 키 | 내용 |
|---|---|---|---|
| 매장명 | **HEADLINE** | `headline` | 가게·장소 이름 |
| 📍위치 | **SUBHEADLINE** | `subtext` | **구글맵 주소 그대로, 우편번호 포함.** 한 줄이 넘치면 **2줄**로 넣는다. `📍` 를 앞에 붙인다 |
| 특징 설명 | **BODY** | `body` | **3~4줄.** 요다체, 관광객 타겟 (→ 아래 말투 규칙) |
| 배경 이미지 | (레이아웃 배경) | `user_image_urls` | **사람이 고른 사진 1장** (매장당 후보 5장 중에서) |

- **키 이름 주의**: SUBHEADLINE 슬롯이 읽는 값은 `subheadline` 이 아니라 **`subtext`** 다
  (`backend/app/services/carousel_renderer.py:106-125`).
- **세 칸을 한 칸에 뭉치지 않는다.** 칸마다 다른 슬롯으로 들어간다.
- 낱장에 그 역할 슬롯이 없으면 **에러가 아니라 그 칸만 조용히 사라진다.**

## 위치는 **구글맵 주소를 글자 그대로** 쓴다

표지·`CTA2` 배경이 실제 장소 사진이 아니라 지도 캡처다(→ [3-2단계](지도_3-2단계_썸네일이미지.md)).
배경이 장소를 보여주지 않으므로 **어디인지는 본문의 위치 칸이 짚어 준다.**

- 주소를 **글자 그대로** 옮긴다. 이 주소가 곧 구글맵에 뜨는 주소다.
- **우편번호(`〒604-8055` 같은 맨 앞부분)도 포함한다.** 주소에서 빼는 것은 **아무것도 없다.**
  단, **국내 주소는 가이드가 우편번호 없이 준다.** 없는 번호를 지어내지 말고 있는 그대로 쓴다 (2026-08-27 추가).
- 한국어 지역명으로 바꾸거나 요약하지 않는다. **건물명·층까지 그대로** 넣는다.
- 주소 출처는 **`read_travel_guide` 원본**이다. 2단계 표는 옮겨 적는 과정에서 건물명이 줄어 있을 수 있다. **원본이 맞다.**
- **가이드에 없는 지역이면** 2단계에서 웹 검색으로 확인한 주소를 쓰고, **우편번호도 그 자리에서 웹으로 확인한다.**
  기억이나 짐작으로 적지 않는다.

### 가이드 주소와 구글맵 주소가 다르면 — **구글맵을 쓰고 사람에게 말한다** (2026-08-28 4회차 추가)

가게가 **이전하면 가이드 주소가 낡은 주소로 남아 있다.**

- 위치 칸은 「구글맵에 뜨는 주소」가 목적이므로 **`place_info` 가 돌려준 주소를 쓴다.**
- 다만 **말없이 바꾸지 않는다.** 본문을 낼 때 「가이드는 ○○, 구글맵은 □□ — 이전한 것으로 보인다」고 한 줄 붙인다.
- 4회차 실제 예 — 임순이네밥집: 가이드 `애월읍 곽지1길 26-7` ≠ 구글맵 `애월읍 곽지9길 8-1`.
  구글 리뷰에 「이전하기 전도 맛있고」가 있어 이전이 확인됐다.

### 한 줄이 넘치면 2줄로 넣는다

우편번호까지 넣으면 한 줄에 안 들어간다. **줄여서 맞추지 말고 두 줄로 넣는다.**

- `subtext` 값 안에 줄바꿈(`\n`)을 직접 넣어 두 줄을 만든다.
- 끊는 자리는 **우편번호 + 도·부·현 + 시·구 까지가 1줄**, **거리·町·번지·건물명이 2줄**이다.
- 3줄로 넘어가지 않게 한다. 그래도 넘치면 **글자 크기는 사람이 편집기에서 조정**한다.
- **봇이 주소를 줄이거나 건물명을 떼지 않는다.** 길이 문제는 줄바꿈과 글자 크기로 푼다.

```
📍〒104-0061 東京都中央区
銀座4-13-17 高野ビル1F

📍〒810-0001 福岡県福岡市中央区
天神2-14-13
```

## 특징 설명은 **가이드 후기요약(blurb)에서 가져온다**

`read_travel_guide` 의 `blurb`·`tip` 에 있는 내용만 쓴다. 없는 장점을 붙이지 않는다.
단점도 후기에 있으면 그대로 한 줄 넣는다 — 광고 문구처럼 읽히지 않게 한다.

**가이드에 없는 장소면** 2단계에서 웹 검색으로 확인한 사실(창업연도·운영사·파는 것·시식 여부 등)만 쓴다.

### 평점·영업정보는 **BODY 에 넣지 않는다** (2026-09-04 사람 지시 · 모든 장소에 적용)

확인한 값이라도 적지 않는다. 낡으면 그대로 틀린 정보가 되는데, 올린 캐러셀은 못 고친다.

- 넣지 않는 것 — **평점·별점·리뷰 수**(`4.5점` · `구글 평점 4.2` · `리뷰 500개`),
  **영업시간·영업일·휴무일·브레이크타임·라스트오더**(`매주 화요일 휴무` · `오전 11시 오픈` · `연중무휴`),
  **가격·요금·입장료**.
- 이건 「가이드에 없는 장소」만의 규칙이 아니다. **`blurb`·`tip`·구글 리뷰에 적혀 있어도 마찬가지다.**
- 대신 **분위기·메뉴·먹는 방식·무엇으로 유명한지** 같은 잘 안 변하는 것으로 3~4줄을 채운다.
- 「늦게 가면 재료가 떨어진다」·「점심에는 줄을 선다」처럼 **시각·요일을 못 박는 혼잡 이야기는 된다.**
  다만 `11시 반이면 만석` 처럼 시각을 박지 않는다.
- 이 문서 아래쪽 회차 기록의 「구글맵 평점 4.2 / 리뷰 473」 같은 줄은 **봇이 근거를 적어 둔 메모지 BODY 가 아니다.** 본문에 옮기지 마라.
- 봇이 손으로 `generate_copy` 를 부를 때는 이 줄을 프롬프트에 적어 보낸다 — 원클릭은 이 문서를 통째로 넘기지만 손으로 부를 때는 안 간다.

**B(가이드 기반) 경로에서 가이드에 있지만 `blurb` 가 빈 장소**도 같은 문제다 (2026-08-27 추가).
그때는 **웹으로 그 장소의 사실을 확인해 채우고, 어디서 가져왔는지 사람에게 말한다.**
(2026-08-27 전국 놀이공원 회차 — 코코몽에코파크·마산로봇랜드가 `blurb` 가 비어 있었다.)

> **`blurb` 는 중간에서 잘려 온다** (2026-08-28 4회차 확인). 끝문장이 「호불호가」·「다만 점심시」처럼 끊긴다.
> **잘린 뒷부분을 짐작해 이어 쓰지 말고**, `place_info` 의 리뷰로 확인된 것만 본문에 넣는다.

### 길이 — **3~4줄** (2026-08-28 변경)

**3줄 또는 4줄.** 이전의 「4줄 고정」은 폐기한다.

- 근거가 넉넉하면 4줄, 확실한 사실이 3줄뿐이면 **3줄로 끝낸다.**
- **줄 수를 채우려고 지어내지 않는다.** 없는 장점을 붙여 4줄을 만들 바에는 3줄이 낫다.
- 2줄 이하로 줄지 않게 한다. 사실이 그만큼도 안 모이면 사람에게 말한다.

### 말투 — 요다체, 관광객 타겟

**읽는 사람은 여기 가려는 관광객이다.** 소개글이 아니라 먼저 가 본 사람이 알려주는 말투로 쓴다.

- **요다체** — `~요` 로 끝나는 해요체를 기본으로 하되, 모든 줄을 `~요` 로 끝내지 않는다.
  중간에 `~다`·`~습니다` 를 섞어 리듬을 준다.
- 줄이 전부 같은 어미로 끝나면 읽을 때 티가 난다. **어미를 붙여 쓰지 않는다.**
- 관광객이 실제로 궁금해할 것부터 쓴다 — 뭘 보는 곳인지, 뭐가 유명한지, 언제 가면 나은지.
- **광고 문구 금지.** `최고의`, `놓칠 수 없는`, `필수 코스`, `강력 추천` 같은 말은 쓰지 않는다.
- 감탄사·이모지로 채우지 않는다. 위치 칸의 `📍` 말고 본문에는 이모지를 넣지 않는다.
- **말투를 바꿀 때 어미만 갈아 끼우지 않는다** (2026-09-01 사람 지시). `~다` 를 `~요` 로 바꿔 다는 것으로 끝내면
  문장 구조는 문어체 그대로라 읽을 때 겉돈다. **문장 구조와 호흡을 그 말투의 성격에 맞춰 통째로 다시 쓴다** —
  어순·끊는 자리·조사·군더더기까지 손봐서 처음부터 그 말투로 쓴 문장처럼 만든다. 다른 말투로 바꿔 달라고 할 때도 같다.

## 이미지 — **매장당 5장** (구글맵 3 + 네이버 2) (2026-08-28 변경)

이전의 「장소마다 3장 · 검색은 최후의 수단」은 폐기한다.
**매장마다 구글맵 3장 + 네이버 검색 2장 = 5장**을 항상 함께 낸다. 검색을 건너뛰지 않는다.

| 출처 | 장수 | 도구 |
|---|---|---|
| 구글맵 사진 | **3장** | `place_info(place: "<장소 이름>", photo_count: 8)` |
| 네이버 검색 | **2장** | `search_images(q: "<매장명> <지역>", style: "photo", limit: 10)` |

**둘 다 세로형 · 고화질로 고른다** (→ 아래 규칙).

### 구글맵 3장 — `place_info`

- 그 장소에 **구글맵에 실제로 올라온 사진**만 온다. 다른 가게가 섞이지 않는 것이 이 경로의 장점이다.
  실측(2026-08-28): 제주 민속자연사박물관 67장, 니시키시장 125장, 범일분식 134장, 정성듬뿍제주국 156장, 임순이네밥집 108장.
- 장소 이름만 알면 된다. 가이드의 `place_id` 를 넘겨도 되고, **일본 장소는 `country: "jp"`** 를 함께 준다.
- **받은 사진은 Read 로 열어 보고 고른다.** 무엇이 찍혔는지 확인하지 않고 순위대로 넘기지 않는다.
  동영상이 섞여 오므로(`type` 이 `video`) 그것도 걸러낸다.
- **3장은 세로형부터 채운다** (2026-09-01 사람 지시). 순위가 높다고 가로컷을 먼저 집지 않는다.
  `photo_count` 를 넉넉하게 받아 열어 본 뒤 **세로컷을 먼저 3장 고른다.**
  세로가 3장에 모자랄 때만 정사각 → 가로 순으로 채우고, **가로컷을 넣었으면 그 사실을 말한다.**
  구글맵 사진은 `local_path` 가 오므로 비율을 눈으로 확인할 수 있다 — 네이버처럼 「못 확인」으로 넘기지 않는다.
- 음식 클로즈업·인물 위주라 장소를 못 보여주는 장이 섞여도 빼지 말고 후보에 넣는다.
  다만 **장소가 안 보이는 컷이라는 것은 한 줄로 알려 준다.**
- **3장이 안 나오는 장소(신규·소규모)** 는 몇 장인지 말하고, 모자란 만큼 네이버로 채운다.
  **구글맵 사진이 0장인 곳도 있다** — 2026-08-28 또바기농장이 그랬다. 그때는 전부 검색으로 채우고 그 사실을 말한다.
- **가게가 이전했으면 옛 건물 사진이 섞여 온다** (2026-08-28 4회차). 임순이네밥집은 108장 중 2장이 이전 전 건물이었다.
  **지금 간판과 다른 건물은 후보에서 뺀다.**

> **`read_travel_guide(with_photos: true)` 로 때우지 마라.** 가이드 사진은 한 장소에
> 1장뿐인 경우가 많아(같은 사진의 크기 변형이 두 개 올 뿐) 장수를 못 채우고, 그래서
> 모자란 만큼 **스톡 검색으로 채우다가 그 장소가 아닌 사진이 섞였다.**
> `place_info` 는 그 장소에 붙은 사진만 주므로 이 문제가 없다 (2026-08-28 교체).

### 네이버 2장 — `search_images`

사람 지시: 「앞으로 이미지는 네이버 우선으로 검색해줘. 워터마크 없는 걸로」 (2026-08-27)

- **`profile` 을 빼고 부른다.** 기본 프로필이 `naver → pexels → pixabay → unsplash` 라 네이버가 첫 번째다
  (`backend/app/services/image_search/__init__.py:38`).
- **네이버로 2장이 안 채워지면 그때 `profile: "v2"` 로 보충한다** (`bing → naver → wikimedia`).
  순서를 바꿔 다시 부르는 것이지, 네이버를 건너뛰는 게 아니다.
- 검색어에는 **매장명만 넣지 말고 지역·업종·간판 메뉴를 붙인다.** 같은 이름의 다른 가게가 섞여 들어온다.
- **상호에 `&` 가 들어가면 검색이 깨진다.** `&` 를 빼고 로마자로 다시 넣는다.
  **엉뚱한 결과가 오면 상호 표기를 바꿔 두세 번 다시 검색한다.**
- 스톡 사이트(pexels·pixabay·unsplash)가 내놓는 **어느 장소인지 모를 분위기 사진은 후보에서 버린다.**
  그 장소가 아닌 사진을 그 장소라고 내밀지 않는다.
- 검색 결과가 **정말 그 가게인지 봇은 확신할 수 없다.** 출처가 공식·매체인 것을 위로 올리고,
  어떤 출처인지 한 줄씩 붙여 준다.
- **구글 이미지 검색은 붙어 있지 않다.** 붙은 엔진은 `bing`·`naver`·`wikimedia`·`unsplash`·`pexels`·`pixabay` 여섯 개다
  (같은 파일 `:28-35`). 사람이 구글로 찾아 달라고 하면 **못 한다고 말한다.** 구글인 척 하지 않는다.
- 단, `place_info` 가 주는 사진은 **구글맵 사진이 맞다.** 검색과 헷갈리지 않는다.

### 고화질로 (2026-08-28 사람 지시)

- **화질이 뭉개진 사진, 작은 썸네일은 후보에서 버린다.**
- 빼는 신호: URL 에 `_thumb`·`thumbnail`·`small`·`w200`·`120x120` 같은 축소 변환이 들어간 것,
  블로그 목록용 미리보기 주소.
- 같은 사진의 원본이 있으면 **원본 주소를 쓴다.**

### 세로형으로 (2026-08-27)

**가로보다 세로가 긴 사진(세로형)을 고른다.** 캔버스가 1080×1350(4:5) 세로라,
가로 사진을 배경으로 깔면 cover-fit 으로 **좌우가 잘려 나가** 장소가 반쯤 사라진다
(`backend/app/services/carousel_renderer.py:333` · `_make_image` 의 cover-fit).

- 우선순위: **세로형 > 정사각 > 가로형.** 가로형밖에 없으면 그 사실을 말하고 낸다.
- **`search_images` 결과의 `w`·`h` 는 0 으로 온다.** 비율을 도구가 알려주지 않는다.
  그러니 **URL·파일명으로 판단한다** — 예: `…768x1024.jpg`(세로), `540_720_…`(세로),
  `…1024x768.jpg`(가로), `1000x1000_…`(정사각).
- **bing preview 썸네일 코드도 힌트가 된다** (2026-08-27 관찰): `HaJ4`·`HaJ2`·`HaLH` 는 세로,
  `HaHa` 는 정사각, `HaE7`·`HaE8`·`HaFj`·`HaEK` 는 가로로 나오는 경향이 있다.
  **경향일 뿐이라 단정하지 말고 「추정」이라고 말한다.**
- **네이버 결과는 비율 힌트가 거의 없다** (2026-08-27 확인). `blogfiles.naver.net` 경로는 원본 파일명만 남아
  가로세로를 알 수 없다. 그럴 때는 **모른다고 말하고** 사람이 눌러 보게 한다.
- 배경 위치·크기는 사람이 편집기에서 조정할 수 있다. 링크를 줄 때 그렇게 알린다.

### 워터마크 없는 것으로 (2026-08-27 사람 지시)

**워터마크가 박힌 사진은 후보에 넣지 않는다.** URL 만 봐도 상당수 걸러진다.

- 빼는 신호: `watermark`·`_water`·`l_Klook_water…`(klook 변환)·`logo` 가 들어간 경로,
  예약·티켓 판매 사이트의 미리보기 변환 URL, 쇼핑몰 썸네일.
- 매체·공식·개인 블로그 원본이 안전하다. **뉴스 사진은 사진 위에 언론사 로고가 얹혀 있는 경우가 있다** — 준다면 말한다.
- URL 만으로 확신이 안 서면 **「워터마크는 못 확인했다」고 밝힌다.** 없다고 단정하지 않는다.

### 콜라주 컷도 버린다 (2026-08-28 사람 지시)

**여러 장을 한 장에 이어 붙인 사진은 후보에 넣지 않는다.** 배경은 캔버스 전체에 cover-fit 으로 깔리므로
(`backend/app/services/carousel_renderer.py:333`) 격자로 나누어진 그림은 **칸 하나만 잘려 들어와** 무엇을 찍은 사진인지도 안 남는다.

- 빼는 것: 2분할·4분할 격자 모음컷, 사진 사이에 흰 줄·테두리가 그어진 것,
  메뉴를 여러 장 모아 놓은 컷, before/after 를 나란히 붙인 것, 사진 위에 글자·화살표를 얹은 편집 이미지.
- URL 신호: 경로에 `collage`·`grid`·`tile`·`montage`·`set` 이 들어간 것,
  블로그 본문에 흔한 `1200x1200`·`800x800` 같은 정사각 모음 이미지.
- **구글맵 사진에도 이용자가 올린 콜라주가 섞여 있다.** 구글맵에서 왔다고 그대로 넣지 말고 같은 기준으로 버린다.
- **원격 URL 은 봇이 열어 볼 수 없다.** URL·출처만으로 판단이 안 서면 **「콜라주인지는 못 확인했다」고 밝히고**
  사람이 눌러 보게 한다. 단정하지 않는다.
  단, **`place_info` 사진은 `local_path` 가 오므로 Read 로 열어 직접 확인할 수 있다.**

### 후보 개수 — **매장당 5장을 채운다**

**한 매장에 5장을 채워서 낸다.** 검색이 잘 안 걸려도 4장으로 줄여 내지 말고,
**검색어를 바꿔 다시 찾아 5장을 채운다.** 정말 5장이 안 나오면 **몇 장인지와 왜 그런지를 말한다.**

- 본문 3개는 **각자 자기 장소 사진**을 쓴다. 한 장을 돌려쓰지 않는다.
- 3-2(표지·`CTA2`)는 **지도 캡처**, 본문은 **실사 사진** — 서로 다른 규칙이다. 섞지 않는다.
- `generate_carousel` 의 `user_image_urls` 에 낱장 순번별로 **전체 주소(https://…)** 를 넘긴다.

## 사진은 **매장당 링크 하나로 묶어서** 준다 (2026-08-28 사람 지시)

매장마다 5장을 **링크 하나**로 보낸다. URL 15줄을 대화에 쏟지 않는다.

**`make_gallery` 를 쓴다** (2026-08-28 도구 붙음 — 이전의 "URL 5줄 나열" 임시 형식은 폐기).

```
make_gallery(galleries: [
  {title: "1. 미키케이란 — 사진 5장", images: [
     {url: "…", caption: "구글맵 · 점포 정면 · 세로"},
     {url: "…", caption: "구글맵 · 계란말이 클로즈업 — 가게는 안 보임"},
     {url: "…", caption: "네이버 · 개인 블로그 · 세로 추정"}, …
  ]},
  {title: "2. …", images: [...]},
  {title: "3. …", images: [...]}
])
```

- **매장 3곳을 한 번에** 만든다(`galleries` 배열). 세 번 나눠 부르지 않아도 된다.
- `caption` 이 갤러리 화면에서 그 장의 설명으로 뜬다. **출처·구도·비율을 여기에 적는다** —
  대화에 따로 나열하지 않아도 사람이 화면에서 바로 안다.
- 구글맵·네이버 **외부 주소를 그대로 넣는다.** 앱에 올리는 과정이 필요 없다.
- 돌려주는 `url` 은 전체 주소다. 그대로 대화에 붙인다.
- 갤러리 화면은 **토큰 없이 열린다.** 사람이 눌러서 5장을 나란히 보고 번호로 고른다.
- **한 장소에 갤러리를 두 번 만들지 않는다.** 사진을 다시 찾아 새 갤러리를 만들었으면
  **어느 쪽으로 볼지 그 자리에서 못박는다.** 갤러리가 둘이면 「4번」이 어느 쪽 4번인지 알 수 없다
  (2026-08-28 또바기농장 — 4장짜리와 5장짜리가 둘 다 살아 있어 사람에게 되물어야 했다).

### 전달 형식

```
1. 미키케이란
📍〒604-8055 京都市中京区
錦小路通富小路西入東魚屋町182

(특징 3~4줄)

사진 5장 → https://…/api/galleries/<id>
```

- URL 옆에 **출처(구글맵/네이버)와 무슨 컷인지 한 줄**을 붙인다. **세로/가로도 아는 만큼 적는다.**
- 사람이 **"사진은 편집기에서 직접 고르겠다"** 고 하면 그대로 두고 넘어간다.

## 정확한 정보 확인 필수

**매장명·위치·특징을 지어내지 않는다.** 2단계에서 정한 지도에 실제로 있는 곳만 쓴다.

- 매장명 — 가이드 원본 표기를 따른다. 가이드에 없는 장소는 2단계 표기를 따르되, **한국어로 적는다**
  (예: `三木鶏卵` → `미키케이란`, `喫茶YOU` → `킷사유`).
- 위치 — 원본 주소를 다시 불러 확인한다. **우편번호까지 확인한다**(국내 주소는 없으면 없는 대로).
- 특징 — `blurb`·`tip` 또는 웹으로 확인한 사실만.
- 확인이 안 되는 항목은 **비워 두고 사람에게 묻는다.** 그럴듯하게 채우지 않는다.
