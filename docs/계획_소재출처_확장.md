## 3. 단계 — 각 단계마다 「됐다」를 확인하고 넘어간다

1. **출처 비중 재기**
   두 계정 최근 60건을 수집해 출처를 태깅한다(수집기는 이미 있다).
   → 검증: 출처별 건수 표가 나오고, 뉴스 비중이 30% 이상인지 본다. (반나절)
2. **뉴스 수집 헬퍼 만들기** — `backend/app/services/news_search.py`
   RSS 3~5곳 → 후보 한 줄(제목 · 원문 URL · 매체 · 게시 시각 · 댓글/반응 수)로 돌려준다.
   X 수집(`x_search.py`)과 **같은 모양**으로 맞춰 뒤 단계를 그대로 쓴다.
   → 검증: 한 번 돌려 조건을 채운 후보가 20건 이상인가.
3. **「일본뉴스」 축 지침서 5장** — 1단계 수집 기준(기간·반응·제외) · 3-1 훅 · 3-2 표지 · 3-3 본문 · 5 캡션.
   → 검증: **대표 확정.** 수집 기준(며칠 · 어떤 매체 · 무엇을 뺄지)은 사람이 정한다.
4. **스튜디오에 축 추가** — `studio_steps.AXES` 에 한 줄(지침서 세트 · 템플릿 · 낱장 이름).
   → 검증: 화면에서 1단계부터 캐러셀 생성까지 한 편이 끝까지 간다.
5. **야간 미리 만들기 예약에 끼우기**
   → 검증: 다음 날 아침 화면에 후보와 미리 만든 10개가 올라와 있다.

## 4. 확정된 것 (2026-10-14 트립앤라이프 지시)

- **기사 사진을 그대로 쓴다.** essl2_2 방식 — 매체 사진을 표지로 쓰고 출처(`@매체명`)를 적는다.
  3-2단계 지침서는 「생성 이미지 대체」가 아니라 **원문 기사 사진 받아오기 + 출처 표기**로 쓴다.
  (기사 사진·본문에 저작권이 있다는 점은 §4 전 버전에 적어 두었고, 그걸 알고 고른 쪽이다.)

  시각을 갖는다. 뉴스는 하루 이틀이면 식으므로 회차 간격은 **사람이 정한 값**을 쓴다(아래 미정).

### 아직 미정

- 뉴스 축 회차 시각 — 몇 번, 몇 시에 돌릴지.
- 수집 기준 — 며칠 안의 기사까지 · 어떤 매체 · 무엇을 뺄지 (3단계 지침서를 쓰기 전에 필요).
- 비중 50+40 = **90%**. 남은 10%를 무엇으로 볼지(자체 기획 · 협찬 · 그 밖) 정해지지 않았다.

### 이 분류가 계획에 주는 영향

- **커뮤니티형이 50%다.** §2 의 순위(뉴스 1 · 커뮤니티 2 · 유튜브 3)는 뉴스 축만 먼저 보고 매긴 것이라,
  커뮤니티·IP 수집이 뉴스와 **동급으로 올라와야 한다.**
- 「한국인만 읽을 수 있는 일본어」는 솔희 방의 **상황별일본어 축과 겹친다** — 새 축을 만들기 전에
  기존 축을 트립앤라이프 계정으로 돌릴 수 있는지 먼저 본다.
- 「인기 일본 IP」는 RSS 로 안 잡힌다(공식 X·공식 사이트 공지). 수집 수단을 따로 정해야 한다.
