- 고르는 기준 (**사람이 바꾸면 여기를 고친다**)

  - 주제 지역 안이거나 **그 지역에서 대중교통으로 갈 수 있는 거리**.
- **3곳을 못 채우면 사람에게 먼저 알린다.** 확인 안 된 숙소로 자리를 메우지 않는다. 2곳으로 줄이거나 범위를 넓히는 것은 사람이 정한다.
- 세 곳은 **가격대를 섞는다** (고급 하나 · 중간 하나 · 가성비 하나). 셋 다 특급이면 주제의 「지원」과 안 맞는다.

### 주소 쓰는 법 (2026-10-22 사람 지시 — 금액 줄을 주소로 바꿨다)

사람 지시 그대로 — 「본문3 레이아웃 subheadline 문구 `▶주소` 로 넣을게」.

- 형식은 **`▶` 뒤에 띄어쓰기 없이 주소** — 보기 `▶강진읍 영랑로 17`.
- 주소는 **아고다·구글 지도 표기 그대로** 쓴다. 확인 안 된 주소는 넘기지 않는다 — 「주소 확인 중」으로 두고 **사람에게 알린다.**
- **시·도·군 같은 상위 행정구역은 떼고 읍·면·동부터** 적는다(캐러셀이 이미 그 지역을 다루고 있어 겹친다). 일본 숙소면 한국어 표기로 **시·구부터**.
- **30자를 넘기지 않는다**(칸 한계). 넘으면 번지 뒤 상세(건물명·동호)를 떼고, 그래도 넘으면 **사람에게 알린다** — 봇이 임의로 더 줄이지 않는다.
- ⚠ **할인·캐시백 금액은 이제 낱장에 안 들어간다.** 제도 금액은 본문②(3-3)에만 남는다.

### ~~금액 쓰는 법~~ — 2026-10-22 **주소로 교체돼 쓰지 않는다** (기록만 남긴다)

사람 지시 그대로 — 「`1박 ~원, 60% 할인 금액:~원`, 또는 `캐시백 ~원`」.
**그 회차 제도가 어떤 꼴이냐로 갈린다.**

| 제도 꼴 | SUBHEADLINE 형식 | 보기 |
|---|---|---|
| 할인율형(60%·50%…) | `1박 OO만원 ➡️ NN% 할인 금액 OO만원` | `1박 18만원 ➡️ 60% 할인 금액 7.2만원` |
| 환급·캐시백형 | `캐시백 OO만원` | `캐시백 10만원` |
| 정액 지원형(1박 3,000엔 등) | `1박 OO만원 ➡️ 지원 후 O만원` | `1박 12만원 ➡️ 지원 후 9만원` |

- **할인 금액 앞에 `➡️` 를 넣는다** (2026-10-22 사람 지시). 쉼표 자리를 화살표가 대신한다 — 쉼표와 함께 쓰지 않는다.
  테스트 934 에서 **캔버스에 제대로 그려지는 것을 확인했다**(네모로 깨지지 않는다). 다른 이모지는 쓰지 않는다.

- **둘째 숫자는 「할인받고 실제로 내는 값」이다** (2026-10-22 사람 확정 — 「실제 내는 값으로」). 깎이는 금액이 아니다.
  할인율형이면 **1박 요금 × (100 − 할인율)%** 다 — 18만원에 60% 할인이면 **7.2만원**(10.8만원이 아니다).
  정액 지원형이면 **1박 요금 − 지원금**이다.
  캐시백형만 예외로 **돌려받는 금액**을 적는다(형식에 「캐시백」이라고 적히므로 헷갈리지 않는다).
- **30자를 넘기지 않는다.** 원 단위를 다 적으면(`1박 180,000원, 60% 할인 금액: 72,000원`) 31자쯤이라 **두 줄로 접히고 HEADLINE 과 겹친다.**
  그래서 **만원 단위**로 줄여 쓴다. 소수 한 자리까지 허용(`7.2만원`).
- **상한을 반드시 적용한다** (2026-10-22 사람 지시 「1박 상품은 1인당 최대 2만엔인데, 캐러셀 내용에 맞춰서 최대 할인 적용된 금액으로」).
  - 계산 — **깎이는 금액 = min(1박 요금 × 할인율, 제도 상한)** · **내는 값 = 1박 요금 − 깎이는 금액**.
  - 상한은 **본문②(3-3)에 적은 값과 같아야 한다.** 「1인당 최대 2만엔」이면 2인 1박 요금에는 **2인분(4만엔)** 을 상한으로 쓴다.
  - 엔화 상한은 **원으로 환산해 비교**하고, 쓴 환율과 환산 날짜를 「이번 회차」에 적는다.
  - 상한에 걸려 할인율대로 안 깎이면 **그 사실을 사람에게 알린다**(캐러셀 숫자와 본문② 숫자가 어긋나 보이기 때문이다).
- **통화는 원**으로 맞춘다(보는 사람이 한국인이다). 엔·달러는 환산해 적고 **환율과 환산 날짜를 「이번 회차」에 적는다.**
- 숫자는 **조회한 값 그대로.** 지어내지 않는다. 1박 요금 기준은 **다음 달 평일 1박 · 2인 · 최저가**, 조회한 곳(공식 홈페이지·아고다·부킹닷컴 중 하나)과 **조회 날짜를 「이번 회차」에 적는다.**
- `place_info` 는 **요금을 주지 않는다** — 1박 요금은 숙소 공식 페이지나 OTA 를 열어 확인한다. 못 구하면 **사람에게 알린다**(빈 금액으로 넘기지 않는다).

### BODY — 일본숙소 축과 같은 짜임·말투 (2026-10-22 사람 지시)

규칙 원본은 [일본숙소_3-3단계_본문.md 「BODY — 2줄, 주제와 이어지게 성의 있게」](일본숙소_3-3단계_본문.md) 다. **거기를 읽고 그대로 쓴다.** 요점만 옮기면 —

- **1줄 = 호텔 소개**(위치·시설) + **「… N성급 호텔」 명사형 맺음**. 성급을 못 찾으면 **「2인 N만원대 호텔」**까지만. `~입니다` 로 늘이지 않는다.
- **2줄 = 그 숙소의 자랑거리 한 가지**(전망·객실·특전·가격·동선) · **`~습니다`체**. 추천 토막(「~할 때 좋아요」)은 넣지 않는다.
- 매체 이름을 앞세운 전언(「쟈란에는 ~로 나옵니다」)은 쓰지 않는다. 확인한 사실을 그 숙소의 장점으로 바로 적는다.
- 쓰지 않는 꼴 — 겹관형절(「~에 자리한」) · 안내문 말투(「~해보세요」) · 전언체 · 반말 종결 · 지어낸 체험.
- 세 장이 **같은 꼴로 시작하지 않게** 한다(지역 이름으로 여는 장을 연달아 쓰지 않는다).
- 성급은 **쟈란·아고다 게재 등급**으로 확인한 것만 쓴다. 못 찾으면 금액 맺음으로 바꾸거나 사람에게 알린다 — 지어내지 않는다.
- codex sol prompt 에는 **일본숙소 문서의 2026-10-13 저녁 확정본(캐러셀 786) 여덟 줄 블록을 보기로 넣는다.**

⚠ **줄 길이만 다르다.** 일본숙소 칸은 40px 인데 **여기는 34px·폭900 이라 한 줄 약 26자**다.
일본숙소의 「24~35자」를 그대로 쓰면 **줄마다 접혀 네 줄이 되고 SUBHEADLINE·HEADLINE 과 겹친다.**

## 이미지 — 실제 사진을 레퍼런스로 다시 그리고, **고르는 건 사람이다** (2026-10-23 개정)

사람 지시 — 「이미지는 실제 숙소 이미지 기반 깔끔하게 생성」 · **「숙소 이미지 고를 수 있게」**(2026-10-23).
전에는 봇이 한 장을 정해 그대로 넣었다 — 이제 **숙소마다 2장을 내고 사람이 고른다.**

2. 숙소마다 **서로 다른 레퍼런스 2장**을 고른다 — 되도록 **객실 1 · 외관(또는 로비·식당·노천탕) 1** 로 결을 달리한다. 글자·간판·사람이 든 장은 뺀다.

4. 프롬프트에 늘 넣는다 — 「사진 속 그 숙소를 그대로 두고 다시 찍은 것처럼」 · **글자·간판·로고 없음**(읽을 수 있는 글자가 한 글자도 보이면 안 된다 · 특정 회사 로고 금지) · 얼굴 보이는 사람 없음 · **아래 1/3 은 글이 앉도록 조용하게**(글이 y990~1166 에 앉는다) · 방 지침서 「이미지 품질」·「구도」 규칙.
5. 만든 뒤 **6장을 다 Read 로 열어 본다.** 실제 사진과 **같은 숙소로 보이지 않으면 다시 그린다.**
6. 6장을 **3-2 묶음 메시지의 같은 갤러리**에 넣고 숙소마다 두 번호를 적어 낸다 → 사람이 숙소마다 한 장을 고른다(보기 `숙소 1-1 / 2-2 / 3-1`). **답을 받고 4단계로 간다.**

   - 고른 세 장이 **서로 다른 장면**인지 본다 — 셋 다 객실이면 사람에게 알린다.
- 구글 사진 URL 은 만료된다 — **내려받아 우리 서버에 올린 뒤** 그 주소를 넘긴다.
