## 모든 유형에 적용되는 규칙

1. **30개를 긁어 20~28개를 후보로 올리고, 맨 앞에 추천 5건**(2026-10-20 트립앤라이프 지시로
   10개에서 올림). 디스코드 메시지에는 **추천 5건만** 쓰고 **전체 목록은 파일로 보낸다.**
   문턱을 채우는 소재가 모자라면 **억지로 채우지 말고 몇 건이 모자랐는지 밝힌다.**
2. **표지** — 세로 4:5, 사진을 꽉 채우고 **아래쪽만** 어둡게, **흰 굵은 2줄**, 줄당 **9~10자**(템플릿 96 표지 칸 950px·92pt 실측 — 11자부터 줄이 접힌다 · 2026-10-22 점검),
   계정 표시(트립초초는 훅 아래, 니혼테레비는 훅 위).
3. **본문 2~4장.** 4장을 넘겨 득 본 유형이 없다. 사진이 하나뿐이면 1장으로 끝낸다.
   **영상이 들어가는 캐러셀은 표지·CTA 두 장만 만든다** → [_영상캐러셀_제작흐름.md](_영상캐러셀_제작흐름.md).
4. **캡션은 두 틀** — `[대괄호 제목]` 기사체(사건·제도) / 줄바꿈 많은 대화체(가십·구경거리).
   어느 쪽이든 **확인 안 된 것은 「확인되지 않았습니다」로 못 박는다.**
5. **수치·URL 은 가공하지 않는다.** 받은 값을 그대로 쓰고, 못 받은 값은 「확인 불가」로 둔다.
6. **장소·가게가 나오면 `place_info` 로 실존·영업시간을 본다**([_공통.md](_공통.md)).
7. **이력은 [X인용_이력.md](X인용_이력.md) 를 공용으로 쓴다.** 축이 생기면 그때 나눈다.
8. **보여주는 형식**은 유형마다 항목만 다르고 뼈대는 같다.

```
[1단계 — 주제 후보 20~28개]  (<유형 이름>)

⭐ 추천 3건
1. <무슨 일인지 한 줄>
   갈래: <그 유형의 갈래 중 무엇인지>
   요약: <한두 줄, 한국어>  · 사진 N장
   낱장: <표지 + 캡처카드 2>   (아래 §낱장 조합)
   <원문 URL> · 조회 N · 좋아요 N · 댓글 N

전체 후보
4. …

[2단계 — 주제 선택] 어느 걸로 갈까요?
```

## 후보 줄에 붙는 꼬리표 — 출처 · 유형번호 · 게이트 (2026-10-23 트립앤라이프 지시)

1단계가 후보마다 설명 줄 맨 앞에 `[출처 · 번호. 유형 · 게이트 N/5]` 를 붙인다.

```
치이카와 제트 기내식에 붉은 생선조림이 나왔다는 사진 2장
[X · 2. 치이카와 · 게이트 4/5] 기내식 사진 2장으로 귀여움이 바로 보임
```

- **출처** — 그 글을 어디서 건졌나. 글 주소(도메인)로 가린다.
  `X` · `스레드` · `유튜브` · `인스타` · **`한국커뮤(디시)`** · **`일본커뮤(토게터)`** 처럼
  커뮤니티는 **이름까지 적는다**(2026-10-23 사람 지시 — 묶어 놓으면 어디서 왔는지 다시 눌러 봐야 했다).
  목록에 없는 곳은 `웹` 이다. 넣는 곳은 코드 `studio_steps._SOURCE_HOSTS` 한 군데다.
- **번호. 유형** — 위 한눈표의 **고정 번호**다. 유형이 안 붙으면 `유형없음`.
- **게이트 N/5** — 아래 「2단계 게이트 5문항」 중 몇 개를 넘겼는지. **3개 미만은 뒤로 보낸다**(버리지 않는다).

## 1단계 수집은 **유형별로 나눠 찾는다** (2026-10-22 트립앤라이프 지시)

사람 지시 — 「1단계 수집 유형별 나누기 진행해」.

- 한 회차에 **유형 3개**를 돌아가며 찾는다. 묶음은 **유형 3 + 공통 2 = 5개**로 그대로다
  (한 묶음에 최대 8분이라 늘리면 회차가 40분을 넘는다).
- **그 유형 지침서 원문을 묶음 요청에 통째로 싣는다** — 키워드·소재원·조회/댓글 문턱·
  되는 것/안 되는 것은 그 유형 문서가 정한다. 공통 지침서와 어긋나면 **유형 쪽이 우선**이다.
- 어느 유형이 도는지는 **날짜로 돈다**(기억해 둘 상태가 없다). 10유형이면 **나흘에 한 바퀴**다(2026-10-23 9·10번 추가).
  예 — 10/22 일본충격뉴스·몰랐던일본·일본인관점의한국 · 10/23 커뮤화제·치이카와·여행준비뉴스.
- **공통 묶음 둘(텍스트·사진·영상)은 남긴다** — 어느 유형에도 안 걸리지만 쓸 만한 글을 놓치지 않으려는 자리다.
- 왜 나눴나 — 공통 지침서 하나로만 찾던 10/22 회차가 **43건 중 치이카와 15 · 커뮤화제 1 ·
  한국인만읽는일본어 2** 로 쏠렸다. 유형마다 키워드가 다른데 한 번에 긁었기 때문이다.
- 코드는 `studio_steps._type_batches` 다. **유형을 늘리면 그냥 `_TYPES` 에 한 줄 더하면 된다.**

# 한국 사람이 반응하게 — 2단계 게이트 5문항

일본에서 터진 글이 한국에서도 터지지는 않는다. **소재를 확정하기 전에 다섯 개를 센다.**

1. **한국인이 그 자리에 설 수 있나** — 가게·역·숙소·공항·편의점처럼 **여행 중 마주치는 자리**인가.
2. **한국이 당사자인가** — 한국인·한국 제품·한일 비교가 걸려 있나(137,536 · 3,743 이 그랬다).
3. **감정이 한 가지로 또렷한가** — 귀엽다 / 훈훈하다 / 어이없다 / 놀랍다 중 하나로 떨어지나.

## ② 유튜브 — `yt-dlp` (키 없이 된다)

이 PC 에 `yt-dlp 2026.08.19` · `ffmpeg 8.1.2` 가 깔려 있다. **API 키가 필요 없다.**

**발견 — 키워드로 조회수순 훑기** (최근 1주):

```
yt-dlp --flat-playlist --playlist-end 20 --print "%(view_count)s|%(channel)s|%(title)s|%(webpage_url)s" \
  "https://www.youtube.com/results?search_query=<일본어 키워드>&sp=CAMSBAgDEAE"
```

- `sp=CAMSBAgDEAE` = **조회수순 + 최근 1주**, `sp=CAMSBAgEEAE` = **조회수순 + 최근 1달**.
  (키워드는 URL 인코딩해서 넣는다. 기간을 넓힐수록 영어권 영상이 섞이니 키워드를 일본어로 조인다.)
- 숏폼이 많은 유형(화제·미녀·치이카와)은 **쇼츠를 따로 훑는다** — 검색 URL 에 `&sp=EgIYAQ%3D%3D`.

**확정 — 고른 영상의 수치와 날짜**:

```
yt-dlp --skip-download --print "%(upload_date)s|%(view_count)s|%(like_count)s|%(comment_count)s|%(channel)s" "<영상 URL>"
```

**내용 파악 — 자동 자막을 받아 읽는다** (일본어 영상도 내용을 그대로 읽을 수 있다):

```
yt-dlp --skip-download --write-auto-sub --sub-lang ja --sub-format vtt -o "tmp/yt/%(id)s.%(ext)s" "<영상 URL>"
```

**사진 — 썸네일과 장면**:

```
yt-dlp --skip-download --write-thumbnail -o "tmp/yt/%(id)s.%(ext)s" "<영상 URL>"   # 썸네일
```

- 특정 장면이 필요하면 영상을 받아 `ffmpeg -ss <시각> -i <파일> -frames:v 1 <out>.jpg` 로 뽑는다.
- **댓글 카드**는 이미 만들어 둔 것을 쓴다 — `node scripts/yt-comment-capture.mjs "<영상 URL>" 6`.

⚠ **키워드를 잘못 걸면 정치·혐오 채널이 상위를 덮는다**(2026-10-20 테스트 — 「日本人 衝撃」은
거의 전부 그랬다). **「外国人インタビュー」·「初来日」·「街の声」 계열**이 쓸 만했다.

**문턱(제안)** — 최근 14일 · 조회 **10만 이상**, 또는 기간 무관 **조회 100만 이상**(명예의전당).
댓글 200개 이상이면 반응 카드를 만들 수 있다.

## X 밖 경로도 1단계가 함께 긁는다 (2026-10-23 트립앤라이프 지시)

사람 지시 — 「네 경로도 1단계에 꽂아둬 · 한국커뮤니티도 뽑아서 넣어」.

- X 검색과 **나란히** 돈다(서로 기다리지 않는다). X 후보 50건 뒤에 **X 밖 후보 20건**이 붙는다.
- 긁는 곳·문턱·제외는 `scripts/collect_sources.py` 가 정한다. **소스를 늘리려면 그 파일의
  목록**(`TOGETTER`·`FEEDS`·`KR_FEEDS`·`KR_PAGES`)에 줄을 더한다. 백엔드는 그 결과를
  후보 꼴로 바꾸기만 한다(`backend/app/services/other_sources.py`).
- 한국 커뮤니티는 **일본이 걸린 글만** 남긴다(제목 키워드). 더쿠 재팬처럼 **게시판 자체가
  일본 전용**인 곳은 제목을 다시 묻지 않는다(`jp_only`).
- ⚠ **RSS 가 막힌 곳이 많다**(2026-10-23 직접 확인) — 디시·클리앙·오늘의유머·네이트판은 404.
  아카라이브는 Cloudflare 라 curl 로만 열리고, 올라오는 글이 Q&A 잡담이라 **꺼 두었다**(되살릴 자리는 남겼다).
- X 가 빈손이어도 **X 밖 후보가 있으면 회차를 살린다**(전에는 502 로 통째로 끝났다).
- 수집 단계는 **제목·수치만 본다.** 본문·사진·일본인 반응은 고른 뒤 연다.
- **X 밖 후보의 3-3 본문은 「원문 기사 사진」을 쓴다**(2026-10-23 붙임 — 방향은 2026-10-14
  대표 확정 「기사 사진을 그대로 쓴다」 · [계획_소재출처_확장](../계획_소재출처_확장.md) 4절).
  X 화면 캡처는 X 게시물 후보에만 있다 — X 밖 후보는 `studio_worker._do_body_web` 으로 간다.
  · 원문 사진을 앞에서부터 한 장씩 본문 장에 붙인다. **관련 기사 썸네일(긴 변 600px 미만)은 버린다.**
  · 원문에 쓸 사진이 없으면 **웹에서 찾아** 채운다(3-2 가 「글만 있는 글」에 쓰는 그 길).
  · **「일본 반응」 장은 안 붙는다** — 답글 캡처는 X 게시물에만 있다.
  · ⚠ **캡션 출처 표기(`@매체명`)는 아직 자동이 아니다** — 확정 사항인데 캡션 단계가 출처를
    못 받는다(`CaptionBody` 에 자리가 없다). 그때까지는 **사람이 캡션에 매체명을 적는다.**

⚠ 그래도 ① 이 X 가 아닌 유형(여행준비뉴스·커뮤화제·일본인관점의한국·충격뉴스·몰랐던일본)은
여전히 X 묶음에서는 후보가 적게 올라온다 — 이제 그 자리를 RSS·커뮤니티 후보가 메운다.
남은 계획은 [계획_소재출처_확장.md](../계획_소재출처_확장.md).

## 남의 영상·남의 글을 쓸 때의 선

1. **영상 프레임을 쓰면 캡션에 채널명을 밝힌다.** 트립초초도 유튜버 소재에서 채널명을 그대로 적었다.
2. **영상을 통째로 올리지 않는다.** 캐러셀은 정지 이미지 2~3장까지다.
3. **일반인 얼굴은 가린다.** 사건 피의자·피해자 얼굴은 쓰지 않는다.
4. **스레드·커뮤니티 글은 캡처 + 번역으로 쓰고 개인 계정명은 가린다.**
5. 저작권이 있는 IP(치이카와 등)의 그림은 **다시 그리거나 합성하지 않는다.**
