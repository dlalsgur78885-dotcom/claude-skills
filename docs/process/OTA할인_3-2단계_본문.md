## 본문 이미지 칸 — 그 이벤트 배너 캡처 (2026-09-15 사람 지시)

> 사람 말 그대로 — 「ota할인 캐러셀 본문 이미지 위치에 해당 이벤트 배너 캡쳐 이미지 넣는 것도 지침서에 추가해줘」

- `본문(OTA할인)` 에는 **정사각 이미지 칸 650×650**(x 215 · y 100)이 있다(84·87 같다). 여기에 **그 장 이벤트의 배너 캡처**를 넣는다. 본문마다 다른 배너다.
- **캡처는 이벤트 원문 페이지의 상단 배너**다. 새로 그리거나 생성하지 않는다.
  - 모바일 화면(폭 440)으로 열어 배너 영역만 찍는다. 칸이 정사각이라 **배너 높이만 폭과 같게 늘려** 찍는다 — 글자·그림은 원본 그대로다(2026-09-15 표지 배너와 같은 방식, 사람 확인 「그대로 쓸게」).
  - 찍은 뒤 Read 로 열어 이벤트명·기간 글자가 잘리지 않았는지 본다.
- **원문 페이지가 없거나 막히면**(삭제·봇 차단 — 보도자료로만 확인한 이벤트) 배너를 지어내지 않고 **그 장은 비워 두고 사람에게 알린다.**
- 단일 이벤트 주제는 표지 칸(709×565)과 본문 칸(650×650)이 같은 이벤트다. 비율이 달라 **각각 따로 캡처**한다.
- 넣는 방법(칸 순서 · 배경 에셋)은 [OTA할인_4단계_편집링크.md](OTA할인_4단계_편집링크.md) 「본문 이미지 칸」.
- 회차 기록에 이벤트마다 배너 URL 을 함께 적는다.

## 문구는 codex sol 로 짓는다 (2026-09-15 사람 확인)

방 지침서 「문구 후보는 codex sol 로 짓는다」가 이 단계에도 적용된다 — **세 칸 문구를 봇이 직접 쓰지 않는다.**
(2026-09-15 1·2회차는 원문 사실을 봇이 직접 옮겨 적었다. 그래서 명시한다.)

- 순서: **원문을 먼저 확인** → 확인한 사실(금액·노선·기간·곁들이 혜택)을 목록으로 만들어 prompt 에 싣는다 → codex 가 세 칸을 짓는다.
- prompt 에 이 문서의 「칸 배분」·「틀에 안 맞는 이벤트」 규칙을 **그대로** 싣는다. codex 는 지침서를 읽지 않는다.
- 돌아온 문구의 **숫자·날짜·요일을 원문 목록과 한 글자씩 대조**한다. 목록에 없는 숫자가 있으면 고치지 말고 규칙을 더 적어 다시 부른다.
- 봇이 정하는 것은 사실 목록과 대조까지다. 문장 자체는 codex 결과를 쓴다.

## 확인은 원문으로

- **대시보드 요약만 믿지 않는다.** 이벤트 원문(항공사·OTA 페이지, 막히면 보도자료)을 열어 조건·기간을 확인한다.
- 대시보드의 할인 배지는 틀릴 수 있다 — 2026-09-14 토스페이먼츠 「0.3% 즉시할인」 이 배지에 **3%** 로 찍혀 있었다.

## 틀에 안 맞는 이벤트

- **할인율이 없으면** 제목에 **원문의 최저가를 노선과 함께** 쓴다 — `오사카 편도 73,700원~` (2026-09-15 사람 지시 — 「본문에 들어가는 내용이 아쉬워」).
  「편도·왕복·총액」은 원문에 적힌 대로만 붙인다.
  - **가격도 없을 때만** 혜택 모양을 크게 — `전 노선 특가` · `쿠폰 4종` · `1+1`
- **곁들이 혜택**(경품·추첨·할인코드·적립)이 있으면 대상·조건 뒤에 **`+` 로 하나만** 붙인다 — `일본·베트남 6개 노선 특가 + 왕복 구매 시 365명 경품 추첨` (2026-09-15).
  고를 때는 받는 사람이 많거나 금액이 큰 쪽. 인원·금액은 원문 값만.
- **마감이 3일 안이면**(오늘 포함) 기간 칸에서 시작일을 빼고 **마감부터** 쓴다 — `9/16(수) 23:59 마감 · 탑승 내년 3/27까지` (2026-09-15).
  마감 시각은 원문에 있을 때만 쓰고, 없으면 날짜만(`9/16(수) 마감`).
- **기간이 없으면** — `매주 금요일` · `상시 진행` · `선착순 마감`
- **혜택이 여러 겹이면**(마일+캐시백, 등급별 할인) 제목엔 **가장 큰 하나만**(`최대 24만원 캐시백`), 나머지는 대상·조건에
